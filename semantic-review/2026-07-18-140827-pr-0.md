# Selección y prueba de micrófono

La funcionalidad enumera entradas NAudio, prueba el nivel sin guardar audio, usa el dispositivo elegido al grabar y persiste la preferencia por nombre. La compilación completa pasa sin advertencias, pero quedan fallos concretos de persistencia y sincronización del medidor, además de una identidad de dispositivo insuficiente para restaurar la selección con fiabilidad. No encontré bloqueantes de severidad alta.

**Watch for:** **confirmado, severidad media**, el primer guardado puede fallar si `%LOCALAPPDATA%\LecturIA` aún no existe; **confirmado, severidad media**, callbacks ya encolados pueden dejar un nivel distinto de cero después de detener la prueba; **probable, severidad media**, nombres de dispositivo duplicados o truncados pueden restaurar otro micrófono.

## High-level view

La selección se guarda inmediatamente, incluido el dispositivo elegido automáticamente al iniciar. `AppSettings.Save` escribe directamente el archivo sin crear su directorio, por lo que una instalación nueva puede mostrar un error y no conservar la selección.

Los niveles se trasladan al dispatcher mediante `BeginInvoke`. Al detener, el cero se aplica de inmediato en el hilo UI, pero actualizaciones anteriores que sigan en la cola pueden sobrescribirlo.

La restauración compara exclusivamente `WaveInCapabilities.ProductName`. Ese texto no identifica de forma única un endpoint y puede repetirse, por lo que la preferencia puede apuntar a otra entrada en la siguiente sesión.

<details>
<summary>Issues (3)</summary>

1. **Directorio de preferencias ausente, severidad media, confirmado** - `AppSettings.Save` debe crear `%LOCALAPPDATA%\LecturIA` antes de escribir, idealmente mediante `AppPaths.EnsureCreated()`.
2. **Nivel residual después de detener, severidad media, confirmado** - invalide o cancele actualizaciones pendientes y descarte niveles cuando `IsTestingAudio` sea falso antes de fijar el medidor en cero.
3. **Identidad ambigua del micrófono, severidad media, probable** - persista un identificador estable y único del endpoint, no solo `ProductName`, y resuelva ese identificador al índice NAudio vigente al iniciar.

</details>

<details>
<summary>Details</summary>

## El guardado inicial depende de que otro subsistema cree la carpeta

**Severidad media, confirmado.** `LoadAudioInputDevices` asigna el dispositivo persistido o el primero disponible (`MainViewModel.cs:795`), y esa asignación ejecuta inmediatamente `OnSelectedAudioInputChanged` (`MainViewModel.cs:336`). El controlador llama a `AppSettings.Save`, que usa `File.WriteAllText` directamente (`AppSettings.cs:88`), mientras `AppPaths.EnsureCreated` no se invoca aquí. En una instalación sin `%LOCALAPPDATA%\LecturIA`, la inicialización muestra un error y la preferencia no se guarda; la misma selección seguirá fallando hasta que otra operación cree la carpeta. `Save` debe asegurar el directorio antes de escribir el JSON.

## Actualizaciones encoladas pueden reactivar visualmente el medidor

**Severidad media, confirmado.** `OnInputLevelChanged` (`MainViewModel.cs:726`) usa `Dispatcher.BeginInvoke` para cada bloque recibido desde NAudio. Al detener desde el hilo UI, `StopInputTest` emite cero y `ToggleAudioTest` vuelve a asignar cero, pero ninguna ruta invalida callbacks no cero ya encolados. Si el dispatcher procesa uno después, `AudioInputLevel` queda con un valor residual aunque `IsTestingAudio` sea falso. Conviene asociar las actualizaciones a una generación de prueba o conservar y cancelar una única `DispatcherOperation`; como mínimo, el callback despachado debe descartar el nivel cuando la prueba haya terminado.

## ProductName no restaura de forma inequívoca el endpoint

**Severidad media, probable.** La enumeración expone solo `DeviceNumber` y `WaveInCapabilities.ProductName` (`NAudioRecorder.cs:63`), mientras la configuración conserva únicamente ese nombre (`AppSettings.cs:60`) y selecciona la primera coincidencia. Dos micrófonos con el mismo nombre hacen que el reinicio elija silenciosamente el primero. La solución robusta es persistir el identificador estable del endpoint, por ejemplo el ID de `MMDevice`, y mapearlo al backend de captura; si se conserva WaveIn, debe definirse una estrategia explícita para nombres duplicados.

</details>
